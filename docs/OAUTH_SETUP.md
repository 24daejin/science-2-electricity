# (선택/추후용) GCP OAuth 클라이언트(GIS) 설정 가이드

> **현재 이 플랫폼은 이 문서의 절차를 쓰지 않습니다.** 담당 교사 계정이 교육청 정책으로 Google Cloud Console 자체에 접근할 수 없어(개인 Gmail 계정으로 시도해도 동일하게 막혀 있음 확인됨), 대신 자체 로그인(학번+이름+반코드 / 교사 이름+비밀번호)으로 전환했습니다 — 자세한 내용은 [README.md](../README.md)와 [DEPLOY.md](DEPLOY.md)를 참고하세요.
>
> 이 문서는 나중에 정책이 바뀌거나, Cloud Console 접근 권한이 있는 분(학교 IT 담당 부서 등)을 통해 GIS로 전환하고 싶을 때를 위해 남겨둡니다.

Google Identity Services(GIS)로 학생 로그인을 학교 구글 워크스페이스 도메인에 한정하려면, Google Cloud Console에서 **OAuth 2.0 클라이언트 ID(웹 애플리케이션용)**를 하나 발급받아야 합니다.

> Cloud Console 접근 권한이 있는 분(학교 워크스페이스 관리자, IT 담당 부서 등)께 이 문서를 그대로 전달해 진행을 요청하면 됩니다. 아래 단계만 따라 하면 됩니다.

## 1. Google Cloud 프로젝트 만들기
1. [console.cloud.google.com](https://console.cloud.google.com) 접속 (학교 워크스페이스 관리자 계정 또는 위임받은 계정으로 로그인).
2. 상단 프로젝트 선택 → **새 프로젝트**. 이름 예: `전기와자기-학습플랫폼`.

## 2. OAuth 동의 화면 구성
1. 좌측 메뉴 **API 및 서비스 → OAuth 동의 화면**.
2. User Type: 학교 워크스페이스 조직 내부용이면 **내부(Internal)**를 선택하는 것이 가장 안전합니다(조직 도메인 사용자만 로그인 가능). 조직 계정이 아니거나 내부 옵션이 없다면 **외부(External)**를 선택하고, 아래 4단계처럼 앱을 "테스트" 또는 "게시" 상태로 유지하세요.
3. 앱 이름: `전기와 자기 학습 플랫폼`, 사용자 지원 이메일, 개발자 연락처 이메일을 입력합니다.
4. 범위(Scopes)는 추가할 필요 없습니다(GIS 로그인은 기본 프로필/이메일 정보만 사용).
5. 저장.

## 3. OAuth 클라이언트 ID 발급
1. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**.
2. 애플리케이션 유형: **웹 애플리케이션**.
3. 이름: `GitHub Pages 프론트엔드` (자유롭게).
4. **승인된 자바스크립트 원본(Authorized JavaScript origins)**에 GitHub Pages 배포 주소를 추가합니다:
   - `https://<계정 또는 조직>.github.io`
   - (프로젝트 페이지인 경우 저장소 이름 하위 경로까지는 넣지 않고, origin만 등록합니다 — 예: `https://myschool.github.io`)
   - 로컬 테스트용으로 `http://localhost:8080`도 추가해두면 편합니다.
5. **승인된 리디렉션 URI**는 비워둬도 됩니다(GIS의 ID 토큰 방식은 별도 리디렉션이 필요 없습니다).
6. 만들기를 누르면 **클라이언트 ID**(`....apps.googleusercontent.com` 형태)가 발급됩니다. 클라이언트 보안 비밀(secret)은 이 방식에서는 사용하지 않습니다.

## 4. 발급받은 클라이언트 ID로 실제 전환하기
클라이언트 ID를 발급받았다고 바로 전환되지는 않습니다 — 현재 코드베이스는 자체 로그인(학번+이름+반코드) 방식으로 되어 있으므로, GIS로 되돌리려면 코드도 함께 되돌려야 합니다:

1. `frontend/index.html` / `frontend/assets/js/auth.js`를 GIS 로그인 버튼 방식으로 복원(과거 구현은 git 히스토리 또는 담당 개발자에게 요청).
2. `frontend/assets/js/config.js`에 `GOOGLE_CLIENT_ID`, `SCHOOL_DOMAIN` 값 추가.
3. `apps-script/Auth.js`를 ID 토큰을 `tokeninfo` 엔드포인트로 검증하는 방식으로 복원하고, Apps Script 스크립트 속성에 `GOOGLE_CLIENT_ID`, `SCHOOL_DOMAIN` 추가.

전환이 필요해지면 담당 개발자(또는 이 프로젝트를 만든 대화 이력)에게 "GIS로 되돌려달라"고 요청하세요.

## 5. (외부 앱으로 만든 경우) 게시 상태 확인
User Type을 **외부**로 만들었다면, OAuth 동의 화면이 "테스트" 상태인 동안에는 미리 등록한 테스트 사용자만 로그인할 수 있습니다. 전체 학생이 로그인하려면:
- 동의 화면을 **게시(Production)** 상태로 전환하거나,
- 테스트 사용자 목록에 학생 전원의 이메일을 등록해야 합니다(비현실적이므로, 게시 상태 전환을 권장합니다).

게시 후 Google의 검증(verification) 요청이 뜰 수 있는데, 이 앱은 민감한 범위를 요청하지 않으므로(기본 프로필/이메일만) 별도 검증 없이 게시가 가능한 경우가 많습니다.

## 왜 서버(Apps Script)에서 한 번 더 검증하나요?
GIS의 `hd` 파라미터는 로그인 화면에서 도메인을 "필터링"해 보여주는 UX 장치일 뿐, 브라우저 요청은 조작될 수 있습니다. 그래서 Apps Script(`apps-script/Auth.js`)가 프론트에서 받은 ID 토큰을 Google의 `tokeninfo` 엔드포인트로 다시 검증해 `aud`(클라이언트 ID)와 `hd`(도메인)을 재확인합니다. 이 서버측 검증이 실제 보안 경계입니다.
